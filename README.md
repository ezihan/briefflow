# ⚡ BriefFlow（ブリーフ・フロー）

**〜「読む手間」をゼロにし、1日3分で社会の動きを掴むAIパーソナライズド・ニュースアプリ〜**

## 📌 1. 開発背景と課題（Background & Problem）

情報過多の現代において、日々のニュースを追うことは重要である一方、以下のような課題（ペインポイント）が存在します。

- **情報のノイズが多い**：ゴシップや重複記事が多く、本当に重要なニュースが埋もれてしまう。
- **読む時間とコストが高い（タイパの悪さ）**：長文の記事を毎日精読するのは負担が大きく、ニュース離れにつながっている。
- **自分との関連性が分かりにくい**：そのニュースが自分のキャリアや生活にどう影響するのかが直感的に分からない。

これらの課題を解決するため、**「探さない、迷わない。AIが選び抜いた『今日知るべきこと』だけを3分で把握できる」**ニュースキュレーションアプリを開発しました。

---

## ✨ 2. 主な機能（Core Features）

1. **公式RSSからのリアルタイム自動収集**
   - 著作権や利用規約に配慮し、スクレイピングではなくNHKニュースの公式RSSフィードから最新記事を取得。
2. **AIによる「3行要約」と「カテゴリ分類」**
   - Gemini APIを活用し、長文ニュースの核心を突く3行要約（各40文字以内）を自動生成。
3. **パーソナライズされた重要度スコアリング（S / A / Bランク）**
   - ユーザーの属性・興味関心（例：IT業界志望、AI技術、経済動向など）に基づき、各記事の重要度を **S（必読）・A（推奨）・B（流し読み）** の3段階で評価し、「なぜ重要なのか」の選出理由を1行で提示。

## 💡 4. 技術的な工夫・アピールポイント（Engineering Highlights）

### ① Pydanticを用いた構造化出力（型安全性の担保）

LLMの出力は揺らぎが発生しやすいため、`Pydantic` の `BaseModel` を用いてスキーマ（`NewsEvaluation`）を厳格に定義し、Gemini APIの `response_schema` に指定しました。これにより、フロントエンド側でのJSONパースエラーを100%防いでいます。

### ② 外部APIの障害・混雑に強いフォールバック機構（耐障害性の向上）

開発中、特定のLLMモデルへのアクセス集中による `503 Service Unavailable` エラーやモデル仕様変更による `404 Not Found` エラーに直面しました。
これに対処するため、以下の**3段階のフォールバック（縮退運転）機構**を実装し、システムの耐障害性（Fault Tolerance）を高めています。

1. アカウントで利用可能なモデル一覧を動的に検出し、高速な `flash-lite` 系モデルから優先的に試行。
2. タイムアウト設定および例外処理（`try-except`）により、メインモデルが混雑（503）している場合は自動的に別モデルへ切り替え。
3. すべての外部APIが応答しない緊急時でもシステム全体が停止しないよう、モックデータ（Fallback Data）を返却してフロントエンドの動作を継続させる設計。

### ③ ハルシネーション対策

事実に基づいた正確なニュース要約を生成するため、プロンプトでの制約に加えて `temperature=0.2` と低く設定し、LLMのランダム性（幻覚の発生）を抑制しています。また、必ず元記事（NHK）へのリンクを明記し、情報の透明性を確保しています。

## 🚀 5. ローカルでの実行方法（How to Run）

```bash
# 1. リポジトリのクローン
git clone [https://github.com/あなたのGitHubユーザー名/briefflow.git](https://github.com/あなたのGitHubユーザー名/briefflow.git)
cd briefflow

# 2. 仮想環境の作成と有効化
python -m venv .venv
source .venv/bin/activate  # Windowsの場合: .\.venv\Scripts\activate

# 3. 依存パッケージのインストール
pip install -r requirements.txt

# 4. 環境変数の設定（.envファイルを作成し、Gemini APIキーを設定）
echo "GEMINI_API_KEY=あなたのAPIキー" > .env

# 5. FastAPIバックエンドサーバーの起動
uvicorn main:app --reload
```

サーバー起動後、`index.html` をブラウザで開くとアプリケーションが動作します（API仕様書は `http://127.0.0.1:8000/docs` から確認可能です）。
